# Cursor AI Rules for the Penthouse Project

This file provides rules and context for the Cursor AI assistant working on the "penthouse" project.

## 1. General Rules

*   **Project Name:** The project has been renamed. The backend is `penthouse-backend` and the frontend is `penthouse-frontend`.
*   **No Hallucination:** Do not invent file paths, function names, dependencies, or API endpoints. Base all suggestions on the provided context, conversation history, and project files.
*   **Check Existence:** Before suggesting creating a file or resource, verify if it already exists using available tools.
*   **Avoid Repetition:** Do not suggest actions or code changes that have already been completed or discussed, unless specifically asked to revisit them.
*   **Use Context:** Refer to conversation history, attached files (especially roadmaps and plans), and current file content to maintain context.
*   **Follow Plans:** Adhere to the steps and decisions outlined in `NFT_IMPLEMENTATION_ROADMAP.md` and `PROJECT_RENAME_PLAN.md` unless explicitly instructed otherwise.
*   **Be Specific:** Provide clear, actionable instructions and code snippets.

## 2. Project Structure & Naming

*   **Root Directories:**
    *   Frontend: `penthouse-frontend`
    *   Backend Monorepo: `penthouse-backend`
*   **Backend Apps:**
    *   API: `penthouse-backend/apps/penthouse-api`
    *   Batch: `penthouse-backend/apps/penthouse-batch`
*   **Smart Contracts:** Reside within the backend monorepo, likely under `penthouse-backend/contracts/` or `penthouse-backend/packages/contracts/` (location established during Hardhat setup).
*   **Consistency:** Use these exact names and paths when referring to project parts.

## 3. Frontend (`penthouse-frontend`)

*   **Framework:** Next.js (v14), React (v18).
*   **Language:** TypeScript.
*   **Package Manager:** Yarn (use `yarn add`, `yarn install`, `yarn dev`, `yarn build`).
*   **UI Library:** Material UI (MUI v5).
*   **State Management/Data Fetching:** Apollo Client (GraphQL).
*   **Web3 Libraries:** `wagmi@^2.9.0`, `ethers@^5.7.2`, `@tanstack/react-query` (peer dep for wagmi v2).
*   **Key Directories:** `pages/` (or `app/`), `components/`, `lib/`, `graphql/`, `styles/`, `public/`.
*   **Scope:** Contains only frontend code. Do not add backend logic, database models, or direct database connections here.

## 4. Backend (`penthouse-backend`)

*   **Framework:** NestJS (v10) Monorepo.
*   **Language:** TypeScript.
*   **Package Manager:** NPM (use `npm install`, `npm run build`, `npm run start:dev`, etc.).
*   **API:** GraphQL (via `@nestjs/graphql`, `@nestjs/apollo`).
*   **Database:** MongoDB (via `@nestjs/mongoose`).
*   **Web3 Library:** `ethers@^5.7.2`.
*   **Key Directories:** `apps/penthouse-api/`, `apps/penthouse-batch/`, `libs/` (for shared modules).
*   **Scope:** Contains backend logic, API definitions, database interactions, smart contract interactions. Do not add frontend UI components or logic here.

## 5. Smart Contracts (`penthouse-backend/contracts`)

*   **Language:** Solidity.
*   **Framework:** Hardhat.
*   **Standard:** ERC-721 for property NFTs.
*   **Base Contracts:** OpenZeppelin Contracts (`@openzeppelin/contracts@^5.0.0`).
*   **Target Blockchain:** Polygon (Mumbai for testnet, PoS for mainnet).
*   **Tooling:** Use `npx hardhat compile`, `npx hardhat test`, `npx hardhat run scripts/deploy.ts --network mumbai`, etc.

## 6. API & Communication

*   **Primary:** Frontend communicates with the `penthouse-api` backend via GraphQL.
*   **Backend <-> Blockchain:** The `penthouse-backend` interacts with the deployed smart contract via `ethers.js` and an RPC provider (Alchemy).
*   **Frontend <-> Wallet/Blockchain:** The `penthouse-frontend` interacts with the user's wallet (MetaMask) and reads contract state/triggers transactions via `wagmi`.
*   **No Direct Imports:** Frontend MUST NOT directly import code from the backend filesystem, and vice-versa. Communication occurs via the defined GraphQL API.

## 7. Tooling & Commands

*   **Frontend:** Use `yarn` for all package operations in `penthouse-frontend`.
*   **Backend:** Use `npm` for all package operations in `penthouse-backend`.
*   **Hardhat:** Use `npx hardhat ...` commands from within the `penthouse-backend` directory (or wherever the Hardhat project is initialized).
*   **Verification:** Use PolygonScan (Mumbai/Mainnet) websites to verify deployments and transactions externally.
*   **Node Provider:** Use Alchemy via API keys stored securely (likely via NestJS ConfigService / `.env`).

## 8. File Handling & Edits

*   **Check Existence:** Always verify if a file exists before attempting to create it.
*   **Targeted Edits:** When editing existing files, provide only the necessary changes using context and `// ... existing code ...` comments. Avoid replacing entire files unless creating a new one.
*   **Roadmap Adherence:** Base file creation and modifications on the steps defined in `NFT_IMPLEMENTATION_ROADMAP.md`.

## 9. Context & Memory

*   **Prioritize Provided Info:** Use the current conversation, attached files, and explicitly provided context over general knowledge.
*   **Refer to Roadmaps:** If unsure about the next step or project details, re-read relevant sections of `NFT_IMPLEMENTATION_ROADMAP.md` or `PROJECT_RENAME_PLAN.md`.
*   **Ask for Clarification:** If context is missing or ambiguous, ask clarifying questions rather than making assumptions.
